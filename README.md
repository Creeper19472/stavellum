<h1 align="center">Stavellum</h1>

<p align="center"> <a href="./README-zh.md">简体中文</a> | <b>English</b> </p>

A utility for automatic score generation and presentation from supported formats.

Convert FL Studio projects or MIDI into staff notation and scroll it on screen to create polished presentation videos. Import **FLP / MIDI + the original audio**, adjust instruments and notation settings, preview, and export **MP4, MusicXML, and PDF parts**.

The program renders frame by frame instead of capturing the screen. The default output is 1920×1080, 60 fps, H.264 + AAC, with **RHI Vulkan** frame compositing and NVIDIA NVENC encoding preferred, automatically falling back to the CPU when the hardware is unavailable.

## Installation and Launch

For the best performance, your device should have at least **a graphics card and driver supporting Vulkan and 4×MSAA**.

The program currently runs only on Windows x64 and requires Python **3.14**, [uv](https://docs.astral.sh/uv/), and FFmpeg with the `libx264` encoder. Running from source also builds the native Rust Vulkan backend with Cargo (Visual Studio C++ tools or a windows-gnu Rust toolchain; see [Rust build instructions](docs/rust-renderer.md)). The optional legacy Qt RHI backend additionally needs the Visual Studio C++ tools and PySide6 pinned to **6.11.2**.

Add the directory containing `ffmpeg.exe` and `ffprobe.exe` to `PATH`, then run the following in the project directory:

```powershell
uv python install 3.14
uv sync --extra dev --locked
uv run python scripts/build_rust.py --install
ffmpeg -version
ffprobe -version
.\run.ps1
```

You can also run `uv run stavellum gui` or `uv run python -m stavellum gui`. To open an existing project:

```powershell
.\run.ps1 -Project "artifacts/demo/demo.stproj"
```

You can first try a sample generated by the program:

```powershell
uv run stavellum demo --output artifacts/demo --bars 16 --open
```

This generates the sample project's `.stproj`, MIDI, and synthesized WAV files, including ordinary / Pizz articulations, sustained notes, triplets, and silent passages. You can use this sample project to check the program's behavior.

## Quick Start

### Create and Import
1.  Click **New Project** in the “File” menu at the top of the editor or on the welcome screen, select an FLP or MIDI file, and link the original audio (which can also be selected later).
2.  In the wizard that appears, check the track information, Arrangement, tempo, and time signature; then click “Reimport”.

*Note: Opening a saved `.stproj` project file directly restores your previous working state.*

### Confirm Tempo and Time Signature
If an FLP file contains unrecognized automation, the system prompts you to manually confirm the track's overall timing and tempo.

### Manage Voices and Parts
* **Merge and split**: Select multiple parts to merge them (for example, ordinary, Pizz, and Staccato articulations), or split them again by source / MIDI channel.
* **Layout settings**: Configure instrument icons, clefs, key signatures, transposition, quantization, and triplets for each voice, or enable a grand staff and percussion mapping.

### Optimize Notation (Optional)
* **Automatically simplify note notation** (enabled by default): Prefer enharmonic spellings within the key signature (such as E♯ and B♯), greatly reducing unnecessary natural signs.
* **Automatic octave shifts** (disabled by default): When enabled, consecutive passages in high / low registers automatically use **8va, 8vb, 15ma, and 15mb** markings to reduce ledger lines and improve readability.

### Preview and Align
* Click “Update Preview” at the top, and use the playback timeline below to check audio and visual synchronization.
* If the audio and score are misaligned, adjust the **score zero point within the audio** under “Source and Timing” (for example, entering `1.25` means that 1.25 seconds into the audio corresponds to the first beat of the score).

### Export Your Work
* After saving the project file (`.stproj`), use the “Export” menu to export an **MP4 video** or **MusicXML / PDF parts**.

## Main Interface and Parameter Configuration

Use the “Settings” panel to customize the visuals and animations:

* **Track and text information**: Set the title, subtitle, credits, and announcement text, with freely adjustable positions and font sizes.
* **Frame and score layout**: Customize the video dimensions and score margins; when there are fewer voices, the view automatically scales up moderately to improve its appearance.
* **Opening and announcements**:
  * Set the **opening hold** duration for an opening sequence of “static announcement / frame display $\rightarrow$ fade out and smoothly expand the score area $\rightarrow$ start playback”.
  * Configure a timed fade-out for the announcement text.


* **Voice animation and smoothness**:
  * **Animation speed**: Presets include “Fast, Medium, Slow, Very Slow” and a custom option, controlling how long voices take to enter and exit and how long smooth layout transitions take.
  * **Minimum stable time after animation** (2 seconds by default): Prevent voices from frequently hiding, appearing, or flickering in size over short periods; set this to `0` to disable the restriction.


* **Rendering and export**: Video export runs in a separate background process, allowing you to view progress or cancel at any time. If you dismiss the progress window, you can reopen it through “Export Details” at the bottom of the main window.

> [!NOTE]
> Project files (`.stproj`) store only settings and reference paths to input files. If you move or rename the original audio, you will need to manually select it again when reopening the project.

## Optional Features

### Custom Instrument Icons

Click **Choose Icon** next to the icon settings in “Part Correction” to choose built-in project icons, import **SVG / PNG / JPEG / WebP**, or search by English name on the Font Awesome tab (for example, `guitar` or `music`) and filter by source and style.

> [!NOTE]
> SVG files must be self-contained; if they reference external images, first embed those images into the SVG using your graphics software. Also, static icons do not play SVG animations.

The application bundles the Solid, Regular, and Brands styles of **Font Awesome Free 7.3.1**, totaling 2,883 icons available offline. You can also click **Connect Free / Pro Icon Library** and select the root directory, `svgs-full`, or `svgs` of a Font Awesome distribution you have extracted. The application reads its contents only when choosing icons and does not copy the entire icon library into the project.

You can also directly enter an existing icon name (such as `violin`) or a built-in Free name such as `fa:solid:guitar` or `fa:regular:bell`. Leave the field blank to match the instrument automatically; **Restore Automatic** clears the existing selection. Uncheck “Use Instrument Icons” to hide the icons; the icon settings are temporarily disabled while retaining your selection, which is restored when you check the option again. Changing the instrument does not overwrite an explicitly selected icon.

### Display the Software Logo

On the settings page, you can enable “Show the Software Logo in the Bottom-Right Corner”, which is disabled by default. Once enabled, you can choose display modes such as “Always Visible”, “Fade In and Stay Visible”, or “Fade In at the Opening, Hold, Then Fade Out”, and adjust the logo size, maximum opacity, and fade-in / hold / fade-out durations.

If you enjoy this project, consider using this feature to show your support. :)

## Command Line

Arrangement indices for `inspect` / `import` start at **0**. The input names below are examples; replace them with your own files:

```powershell
# Read-only inspection of sources, note counts, and diagnostics
uv run stavellum inspect "song.flp" --arrangement 0

# Create a project for correction in the desktop app; add the confirmation flag only after verifying fixed timing
uv run stavellum import "song.flp" --audio "song.flac" --output "song.stproj" --confirm-fixed-timing

# MIDI fallback entry point
uv run stavellum import "song.mid" --audio "song.wav" --output "song.stproj"

# Open a project and output a PNG frame at a specified audio time
uv run stavellum gui "song.stproj"
uv run stavellum frame "song.stproj" --time 12.5 --output artifacts/frame.png

# Offline frame-by-frame export; dimension / frame-rate overrides affect only this export
uv run stavellum render "song.stproj" --output artifacts/video.mp4 --width 1920 --height 1080 --fps 60 --preset medium

# Explicitly select RHI Vulkan compositing and NVENC; fail immediately if unavailable
uv run stavellum render "song.stproj" --output artifacts/gpu.mp4 --render-backend gpu --video-encoder h264_nvenc --nvenc-cq 18 --nvenc-preset p5

# Force CPU use, or disable automatic recognition for this command only
uv run stavellum render "song.stproj" --output artifacts/cpu.mp4 --render-backend cpu --video-encoder libx264 --no-auto-staccato --no-auto-grace --no-auto-dynamics --no-auto-ottava

# Generate MusicXML and paginated PDFs for each enabled instrument
uv run stavellum parts "song.stproj" --output artifacts/parts
```

`import`, `frame`, `render`, and `parts` all support `--auto-simplify-accidentals` / `--no-auto-simplify-accidentals` to enable / disable notation simplification for all parts. If unspecified, the per-part choices saved in the project are used; new imports enable it by default. Overrides for `frame`, `render`, and `parts` affect only the current output.

Likewise, `--auto-ottava` / `--no-auto-ottava` enables / disables automatic octave shifts for all parts. If unspecified, the project settings are used; new imports disable it by default, and output command overrides are not saved back to the project.

`import` also provides `--bpm` to override the tempo; other layout, animation, key signature, and part corrections are saved through the desktop app or in `.stproj`. `frame --time` uses presentation time, consistent with the preview timeline and video frames: audio time is `max(0, presentation time − opening hold)`. The “score zero point within the audio” remains calibrated relative to the original audio and does not include the opening hold. The total export duration is the opening hold plus the later of the end of the original audio and the end of the offset score, rounded up to a whole number of frames; silence is added if necessary, and the original audio's trailing sound is preserved. Older projects missing the new settings use a zero opening hold, medium announcement speed, and an always-visible announcement; existing custom animation durations are retained. The old tempo display settings are ignored, and a scrolling marking in the first measure is used consistently. Use `--help` to view the full parameters for each command.

## Limitations

- Only fixed tempos and fixed time signatures are currently supported. MIDI tempo / time-signature changes, Type 2, and SMPTE timing are explicitly rejected; there are currently no plans to support a full score editor or automatic audio transcription.
- FLP import expands only Patterns that are actually placed and unmuted in the selected Arrangement; part identities come from the Channel Rack. If an unknown or unverified Playlist layout fails, provide MIDI instead. Do not treat “parsing succeeded without errors” as confirmation that the actual performance has been fully cross-checked.
- FL Studio plugins are not run. The actual sound of Audio Clips is preserved through the original audio; tracks without MIDI notes require supplemental baked MIDI. Layer, Slide, channel arpeggiators, notes generated internally by plugins, fine tuning, and automation have diagnostics or support limitations; reconstructing every sound detail from FLP alone cannot be guaranteed.
- Name recognition, automatic clef / key signature selection, and quantization are all suggestions whose accuracy requires human judgment.

For more information, see [FLP / MIDI Import Guide](docs/importing.md).

## Development and Dependencies

The Rust Vulkan compositor retains the native rendering ABI; the legacy Qt backend remains selectable. The Rust scene evaluation library includes Python bindings and parity tests, but is not yet called by the production rendering pipeline. See [Native build, backend selection and benchmarks](docs/rust-renderer.md).

```powershell
uv run python scripts/build_rust.py --install
uv run pytest -q
uv run ruff check src tests scripts
uv build --wheel
```

The main pipeline is: import and `ProjectIR` → `PartMapping` → conservative recognition and score engraving with shared timing between music21 / Verovio → `CompiledScene` → RHI Vulkan / CPU offscreen compositing → FFmpeg NVENC / x264. Preview and export share `FrameRenderer`, and the horizontal tile cache and GPU texture cache each have capacity limits. The generated Windows x64 wheel includes the native DLL and shaders, so no compilation is needed after installation; rebuilding is required when first running from source or after updating native code. A standalone desktop installer is not yet available.
